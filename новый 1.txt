# 🔷 БЛОК 4. PROCESS MANAGER + EVENT BUS

## 4.1. Запуск задачи
```python
# process_manager.py
import asyncio, subprocess
from core.event_bus import emit_event

async def enqueue_script(script_path: str, args: list[str]):
    proc = await asyncio.create_subprocess_exec(
        sys.executable, script_path, *args,
        stdout=subprocess.PIPE, stderr=subprocess.PIPE
    )
    asyncio.create_task(_wait_and_parse(proc))
```

## 4.2. Парсинг результата
```python
# process_manager.py
async def _wait_and_parse(proc):
    stdout, stderr = await proc.communicate()
    lines = stdout.decode().strip().split('\n')
    event = {}
    for line in lines:
        if ':' in line:
            key, val = line.split(':', 1)
            event[key.strip()] = val.strip()
    
    if proc.returncode == 0:
        await emit_event("task_result", event)
    else:
        await emit_event("task_error", {"error": stderr.decode(), **event})
```

## 4.3. Шина событий (НЕВИДИМАЯ для всех, кроме подписчиков)
```python
# core/event_bus.py
_listeners = {}

def subscribe(event_type: str, handler):
    _listeners.setdefault(event_type, []).append(handler)

async def emit_event(event_type: str,  dict):
    for handler in _listeners.get(event_type, []):
        if asyncio.iscoroutinefunction(handler):
            asyncio.create_task(handler(data))
        else:
            handler(data)
```

Встроенный функционал управления координатами
1. Центральная База Данных (ЦБД)
Новая таблица: user_locations
user_id (int, primary key, foreign key -> users table)
location_id (int, primary key, autoincrement)
name (str) - название точки (например, "Дом", "Дача", "Работа").
lat (float) - широта.
lon (float) - долгота.
is_default (bool) - флаг, указывающий, является ли точка точкой по умолчанию для пользователя.
2. Меню "Настройки"
Новый подпункт: "Мои точки" (или "Координаты", "Локации").
2.1. Просмотр точек: Показывает список сохранённых точек пользователя с кнопками "Выбрать", "Редактировать", "Удалить". Кнопка "Назначить по умолчанию".
2.2. Добавить точку:
Бот запрашивает: "Пришлите геопозицию или введите координаты в формате 'широта, долгота'."
Пользователь отправляет геопозицию или текст.
Бот обрабатывает ввод, определяет название (можно запросить отдельно или использовать "Точка X").
Вызывает scripts/settings/add_location_script.py (аргументы: user_id, lat, lon, name).
Скрипт сохраняет точку в user_locations (ЦБД).
2.3. Редактировать точку: Выбирается точка из списка -> ввод нового названия/координат (через геопозицию или текст).
2.4. Удалить точку: Выбирается точка -> подтверждение -> вызов scripts/settings/remove_location_script.py (аргументы: user_id, location_id).
3. Интеграция в основные функции
При вызове любого центрального скрипта (например, weather_today_script.py, agro_conditions_script.py):
bot.py получает команду от пользователя.
bot.py вызывает core/db/central_db.py -> get_user_locations(user_id).
Если у пользователя только одна точка, или у него есть одна точка, помеченная как is_default, и команда не предполагает выбор точки (например, "Прогноз по умолчанию"), то bot.py автоматически использует эту точку и запускает центральный скрипт с её координатами.
Если у пользователя несколько точек и ни одна не помечена как is_default, или команда предполагает выбор (например, пользователь нажал "Прогноз для..."), то bot.py отправляет сообщение с inline-кнопками, где каждая кнопка соответствует одной из точек (name точки). При нажатии кнопки, bot.py запоминает выбранные координаты и запускает центральный скрипт с ними.
Центральный скрипт получает координаты как аргументы командной строки и работает с ними.
4. Вспомогательные скрипты для настроек (опционально, но логично)
scripts/settings/add_location_script.py: Использует core/db/central_db.py для добавления записи в user_locations.
scripts/settings/remove_location_script.py: Использует core/db/central_db.py для удаления записи из user_locations.
scripts/settings/set_default_location_script.py: Использует core/db/central_db.py для установки флага is_default.
Преимущества:
Унификация: Все функции (Погода, Метео, Атмосфера, Агропрогноз) используют один и тот же механизм получения координат.
Удобство: Пользователь может управлять своими точками в одном месте.
Гибкость: Можно выбирать точку для каждой команды или использовать точку по умолчанию.
Масштабируемость: Легко добавить больше точек или уточнить логику выбора (например, "последняя использованная").
Изоляция: Центральные скрипты не заботятся о том, как координаты были получены. Им просто передаются lat и lon.
Изменения в архитектуре:
core/db/central_db.py должен получить функции:
get_user_locations(user_id)
add_user_location(user_id, name, lat, lon, is_default=False)
update_user_location(user_id, location_id, name=None, lat=None, lon=None, is_default=None)
remove_user_location(user_id, location_id)
set_default_location(user_id, location_id)
bot.py должен содержать логику:
Отображения списка точек с кнопками.
Обработки нажатий на кнопки выбора точки.
Вызова get_user_locations перед запуском центрального скрипта.
Центральные скрипты получают координаты как аргументы и не работают с ЦБД напрямую для получения координат.
